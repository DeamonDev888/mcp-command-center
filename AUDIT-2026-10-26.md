## 1. Verdict global

Le socle sécurité de v0.7.7–0.7.12 **tient** : toutes les corrections des audits 2026-10-24/25 sont en place et revérifiées (auth complète, XSS échappées, secret jamais servi, nonce HMAC à usage unique, CSP, capability resserrée, crypto aux vecteurs officiels). **Plus aucun panic atteignable depuis des données réseau** n'a été trouvé dans probe.rs/manage.rs.

Mais cet audit trouve un **nouveau modèle de défaillance** : la classe « panics » est fermée, la classe **« blocages (hangs) » est ouverte** — `ssh_exec` sans délai global, `kill_tree` no-op sur Unix, verrou `children` détenu pendant un `wait()` : un seul de ces blocages **fige toute la supervision** (polls, auto-restart, UI), le même effet que les panics du poller corrigés en 2026-10-25, mais sans `catch_unwind` possible.

Et le **delta non commité contient un vrai bug de perte de données** (`merge_duplicate_servers`, P1 ci-dessous) : à ne pas commettre en l'état.

## 3. Constats P1

### 3.1 — `merge_duplicate_servers` : perte de données silencieuse (delta non commité)

`src/manage.rs:2535-2583`, appelé **sans condition** en fin de `scan_network` (`:2527`) et de `ssh_discover` (`:3210`). Or `scan_network` tourne **automatiquement ~30 s après chaque boot** si le réseau est activé (`src/lib.rs:544-555`).

Trois défauts combinés :
- la clé de groupe `format!("{}@{}", name, host)` (`:2552`) **ignore le port** : deux instances légitimes du même serveur sur la même machine (ports 3000 et 3001) fusionnent ;
- le repli `server_name.or(label)` (`:2545-2549`) fait que deux entrées **sans nom** (label vide — c'est le défaut de `add`, `manage.rs:3484-3488`) partagent la clé `"@<host>"` (ou `"@local"`) → l'une est supprimée ;
- le merge s'applique aux entrées **manuelles/seed/importées**, pas seulement aux `net-*` découvertes, et la suppression est **persistée** par le prochain `save_config`.

**Déclencheur réel** : deux serveurs HTTP locaux manuels sans label (ou même nom, ports différents) → au boot, l'un disparaît de l'UI et de config.json sans aucune confirmation. **Correctif** : clé = `validate::identity_key` (avec port), ne fusionner que des entrées `net-*`/`via_ssh` dont l'ancien port est confirmé mort, exiger un nom non vide, ne jamais toucher aux `origin` Manual/Seed.

### 3.2 — `ssh_exec` sans délai global : gel de toute la supervision

`src/probe.rs:903-905` : seule `ConnectTimeout` (clampé 2-15 s, `:898`) borne l'exécution ; `cmd.output()` attend la fin de session **sans limite**. Une session stallée (machine qui s'endort, Wi-Fi/VPN coupé, sshd bloqué — OpenSSH sonde toutes les ~2 h par défaut) bloque le thread appelant indéfiniment :

- via `poll_one` → `ssh_probe_server` (`manage.rs:1995`), exécuté dans les threads de `poll_all` → **la boucle de supervision unique s'arrête** (polls, auto-restart, statuts UI) jusqu'au redémarrage ; `catch_unwind` protège des panics, pas des hangs ;
- via les threads détachés de `ssh_discover` (les clics répétés empilent des threads suspendus).

Le nouveau `ssh_health` (delta non commité) hérite du problème : sa promesse d'échec rapide à 8 s n'est vraie que pour « machine injoignable », pas pour « session stallée ». **Correctif** : `spawn` + boucle `try_wait` avec échéance dure + `kill`, et options `ServerAliveInterval=5` / `ServerAliveCountMax=2`.

### 3.3 — `kill_tree` no-op hors Windows : hang permanent du poller

`src/probe.rs:127-130` : sur `cfg(not(windows))`, `kill_tree` ignore le PID. Les chemins d'erreur de `probe_stdio` (`:1940-1941`, `:1989-1990`) et les handlers `kill_stdio`/toggle-off de manage.rs font `kill_tree(pid); child.wait();` → sur Unix, rien n'est tué (stdin encore ouvert dans le scope), et un serveur stdio vivant mais muet fait **bloquer `child.wait()` pour toujours** sur le thread de poll. Windows est épargné (taskkill /F /T). **Correctif** : sur Unix, `child.kill()` (après drop de stdin) en repli.

## 4. Constats P2

### 4.1 — Le prune tue des entrées vivantes, prouvées ouvertes par le scan lui-même
`src/manage.rs:2712-2726` : pour un (hôte, port) déjà connu, le thread par hôte fait `hit = true; … { continue; }` — le port vient d'être prouvé ouvert mais **`last_seen_ts` n'est pas rafraîchi**. Puis `:2595-2607` supprime toute entrée `net-*` avec `last_seen_ts <= now-120`. Déclencheurs : `refresh_secs` autorisé jusqu'à 3600 (`:3864`) — tout serveur distant sain pollé moins souvent que toutes les 2 min est supprimé au scan suivant ; idem pour toute entrée dont le poll échoue >2 min alors que le port répond (refresh seulement sur succès, `:2102`), et pour les entrées `via_ssh` persistées — contrairement au commentaire de la fonction. Correctif : rafraîchir `last_seen_ts` dans la branche known (le `port_open` a réussi) + exempter les entrées `via_ssh` persistées.

### 4.2 — Identité faible `"?@host"` : flip-flop entre deux vrais serveurs
`src/validate.rs:100-106` : `identity_key_weak` projette l'absence de nom sur `"?"` ; or la validation stricte accepte un serveur **sans** `serverInfo.name` (protocolVersion/capabilities seuls). Deux serveurs réels sans nom sur la même machine → `dedup_decide` (`:147`) rend `Replace` → chaque scan supprime l'autre (les ports étant parcourus ascendants, l'entrée oscille entre les deux ports indéfiniment). Correctif : la règle « remplace » exige deux noms `Some` égaux (trim + case-insensitive) ; None-vs-None → `Add`.

### 4.3 — Changement de port sans régénération d'id → ids dupliqués → suppression double
Le Replace du scan (`manage.rs:2771-2772`) et la mise à jour SSH (`:3142-3146`) gardent l'id `net-{ip}.{ancien_port}`. Un autre serveur apparaissant ensuite sur l'ancien port reçoit le **même id** (`:2785`) → `remove` (`servers.retain(|s| s.id != id)`, `:3553`) supprime **les deux** ; toggle/poll ne voient que le premier. Correctif : régénérer `net-{ip}.{nouveau_port}` sur les deux chemins + purger l'ancien id de `settings.server_order`.

### 4.4 — Verrou `children` détenu pendant `kill_tree` + `wait()`
`src/manage.rs:3273-3279` (toggle-off), `:3353-3359` (kill), `:3543-3549` (remove) : si `taskkill` échoue (processus élevé/protégé), `child.wait()` bloque **indéfiniment sous verrou** → tous les pollers (stdio `:2154`, auto-start `:2016`) s'arrêtent, UI gelée. Correctif : collecter le pid, lâcher le garde, tuer/attendre hors verrou, re-lier brièvement (garde `spawning` déjà en place).

### 4.5 — `ssh_discover` (delta non commité) : mise à jour destructive
`src/manage.rs:3140-3159` : `existing.version = version.clone()` et `existing.server_name = raw_name.map(...)` sont **inconditionnels** — une sonde validée sans serverInfo/version (désormais possible) **efface** les valeurs connues ; `label` jamais rafraîchi (un `ip:ancien_port` stagne) ; `via_ssh = true` forcé même sur une entrée **manuelle** de l'utilisateur (qui sondera ensuite en SSH et échouera « machine SSH non enregistrée ») ; les entrées **disabled** passent `Up` et y restent (le poll ne touche pas les disabled). Correctif : ne surcharger que si `Some`, rafraîchir le label depuis le nom, sauter les disabled, ne pas forcer `via_ssh` sur origin Manual.

### 4.6 — Slowloris : 30 s par `read()`, pas d'échéance absolue ni de limite par IP
`src/lib.rs:599-618` : chaque octet reçu reset le timeout ; aucun délai total entre accept et `\r\n\r\n`. `MAX_CONNS = 64` (`:25`) est **global**, pas par IP → 64 sockets à 1 octet/29 s depuis un seul hôte LAN verrouillent le webview, le navigateur local et les sondes de pairs indéfiniment. Correctif : échéance absolue d'en-tête (~10 s) et/ou cap de connexions par IP source.

### 4.7 — Process : le fmt n'est pas passé avant push (récurrent)
4 des 5 derniers runs CI sont rouges sur `cargo fmt --check` (commits `44f3512`, `bc4914d`, `9f0467a`, `1ca4860`) et le **working tree actuel reproduit exactement ce défaut**. Un hook pre-commit (`cargo fmt`) ou un `git commit --quiet` après fmt systématique ferme la classe.

## 6. Vérifié sain (contrôles positifs)

- **Auth** : toutes les routes `/api/*` sauf `/` (sans secret, test de régression) et `/api/hello` (nonce seul) passent `check_access` ; Host/Origin vérifiés avant, pour toutes les méthodes y compris la preuve de pair ; OPTIONS 403 ; Transfer-Encoding et Content-Length dupliqué rejetés ; `/api/action` exige `application/json` ; aucun parser à backtracking (pas de ReDoS).
- **Nonce HMAC** : usage unique sous un seul verrou (pas de TOCTOU), plafonné 1024/TTL 120 s.
- **XSS** : `esc()`/`js()` appliqués à toutes les interpolations dynamiques (labels, tools, logs, stats pairs, badges, SSH, store, réglages en `textContent`) ; `inputSchema` jamais rendu ; seul écart : `${i.kind}` statique (P3-14).
- **Secrets** : `state_json` n'inclut jamais `api_access` ; config.json jamais servi ; `mcc.log` propre.
- **crypto.rs** : SHA-256/HMAC validés NIST FIPS-180 / RFC 4231 (multi-blocs, clé > bloc) ; `ct_eq` à temps constant.
- **SSH** : `ssh_safe` (whitelist alphanumérique + `.-_:`) sur hôte/user, destination fusionnée `user@host` (pas d'injection d'option), `Command::args` sans shell, chemins distants via `mcp_path_safe`.
- **Panics réseau** : plus aucun atteignable — dechunk saturé et borné, slicing sur offsets ASCII trouvés, parses `u16/u32` tous `ok()`-gated ou bornés, deadlines `saturating_duration_since` (couverts par les tests hostiles).
- **Commandes locales** : `spawn_process`/`open_path` en vecteur d'args, `kill_port` ne passe que des PIDs numériques.
- **Dépendances** : core = std + serde_json uniquement ; tauri 2.12.4 (ligne 2.x courante) ; zéro dépendance git dans Cargo.lock.
- **Tauri/capabilities** : CSP identique core/tauri ; capability limitée aux contrôles de fenêtre sur 127.0.0.1:5090-5099 ; pas d'updater.
- **CI** : permissions minimales, aucun `${{ github.event.* }}` interpolé dans un `run:`, secrets hors portée des PR fork ; cache non empoisonnable depuis un fork.

## 7. Plan d'action recommandé (dans l'ordre)

1. **Corriger le delta non commité avant tout commit** : `merge_duplicate_servers` (P1-1 : clé avec port, périmètre `net-*`/`via_ssh`, nom non vide, ancien port confirmé mort) et la mise à jour `ssh_discover` (P2-8 : surcharge conditionnelle, pas de `via_ssh` forcé, skip disabled). Puis `cargo fmt` — le working tree échoue aujourd'hui.
2. **Fermer la classe « hang »** : délai global `ssh_exec` (P1-2), `kill_tree` Unix (P1-3), sortie du verrou `children` (P2-4.4). Un test « poller ne gèle pas » (child rebelle simulé) pour chacun.
3. **Prune/dédup** : rafraîchir `last_seen_ts` dans la branche known du scan (P2-4.1), identité faible exigeant deux noms (P2-4.2), régénération d'id au changement de port (P2-4.3).
4. **Serveur HTTP** : échéance d'en-tête absolue + cap par IP (P2-4.6) ; `Host` requis (P3-12) ; `no-store` sur HTML (P3-16).
5. **CI/CD** : réépingler `rust-cache` sur un SHA vérifié (P3-18) ; `cargo fmt` en pre-commit local (P2-4.7) ; SHA256SUMS + CLI npm épinglé dans release.yml (P3-15).
6. **Durcissements P3 à faible coût** : `saturating_sub` (P3-1), garde de ré-entrée scan (P3-5), `${esc(i.kind)}` (P3-14), suppression de la page de secours morte (P3-17).
